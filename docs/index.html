Mothership Documentation

Mothership is a frictionless, real-time collaborative development system. This hub indexes the documentation for every part of the project.

Overview

Mothership replaces the manual commit, staging, and branching workflow with continuous sync. Developers beam into a project, the background daemon tracks file changes, and collaborators see each other's edits in real time over WebSockets.

  • Zero fear: changes are preserved automatically; no destructive operations.
  • Zero ceremony: no manual commits or staging.
  • Zero friction: authenticate once, discover projects, collaborate live.

See the Vision Document for the full philosophy and terminology.

Quick start

Local evaluation build (from the repository root):

# Build all components
cargo build

# Connect to a Mothership server and authenticate
mothership connect https://your-mothership-server.com
mothership auth

# Initialize a project in the current directory
cd your-project
mothership init

# Start real-time collaboration
mothership beam "your-project"

# Stay updated with latest features
mothership update

Full stack with Docker (PostgreSQL included):

# Windows
start-docker.bat

# Linux / macOS
./start-docker.sh

Full command list: see the CLI commands reference in the README.

Common library

The mothership-common crate provides shared types, protocols, diff and merge engines, .mothershipignore rules, and PostgreSQL models. Integration tests live under mothership-common/tests/ (project and rift flows, and wormholes).

Authentication

Machines authenticate once through a browser OAuth flow, and the CLI stores a machine certificate locally. Login and error pages are served from content/:

  • content/login.html
  • content/ghostid-auth.html
  • content/auth-required.html

Access is controlled by the user whitelist; see User Whitelist.

Deployment

Docker files at the repository root:

  • docker-compose.yml: production stack with PostgreSQL
  • docker-compose.dev.yml: development environment
  • docker-compose.override.yml: local overrides applied on top of the base compose file
  • start-docker.bat / start-docker.sh: one-step launchers for the stack
  • Dockerfile.server: server container image (sqlx offline mode)
  • mothership-tunnel.yml: tunnel configuration

Build the server with sqlx offline mode: see SQLX_OFFLINE.md.

Offline sqlx mode: without SQLX_OFFLINE=true, sqlx's compile-time query checks try to reach a live database, and mothership-server fails to build. See SQLX_OFFLINE.md.

Run the test suites per crate:

cargo test -p mothership-common
cargo test -p mothership-cli
cargo test -p mothership-daemon
cargo test -p mothership-server

The chat tests in mothership-server need a PostgreSQL database with the root migrations applied. They are #[ignore]d during normal runs:

TEST_DATABASE_URL=postgres://user:password@localhost:5432/mothership_test SQLX_OFFLINE=true cargo test -p mothership-server chat -- --ignored --test-threads=1

Release-mode profiling tests are #[ignore]d during normal runs:

cargo test -p mothership-cli --release profile_ -- --ignored --nocapture --test-threads=1
cargo test -p mothership-daemon --release profile_ -- --ignored --nocapture --test-threads=1

End-to-end script: scripts/integration-test.ps1 (Windows only). Latest run (2026-11-04, debug build): 20 checks passed, 0 failed. It covers CLI, GUI Neovim saves, daemon sync, rifts, wormhole convergence, and CLI chat send and history. There is no Linux/macOS equivalent yet.

The profiling tests are in mothership-cli/src/profiling.rs, mothership-cli/src/beam.rs, mothership-cli/src/gateway.rs, and mothership-daemon/src/daemon.rs. The chat API tests are in mothership-server/src/chat_api_tests.rs.
